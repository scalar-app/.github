# Governance

Scalar is a personal project that other people are welcome to use and contribute to. This page says how decisions get made, so nobody has to guess.

It is deliberately short. A one person project with a formal committee structure is pretending, and the pretence costs contributors time.

## Who decides

One maintainer, [@martin-k-m](https://github.com/martin-k-m), decides. There is no steering group, no vote and no tie to break.

That means:

- Direction, scope and what gets merged are the maintainer's call.
- A well argued disagreement can change that call. Being ignored is not the same as being overruled, and if a decision seems arbitrary it is fair to ask why in the issue.
- If the project ever has more than one regular contributor, this page changes before anything else does.

## What this project owes you

- **An answer.** Issues and pull requests get a reply, even when the reply is no. Silence is a failure, not a decision.
- **A reason.** Anything closed unmerged gets a sentence saying why.
- **Credit.** Contributions stay attributed. History is not rewritten to remove authorship.

## What it does not owe you

- **A schedule.** Nobody is paid to work on this. There is no service level, no response time and no promise a review happens this week.
- **A merge.** A change can be good work and still not belong in Scalar. Scope is the most common reason.
- **Support for a fork.** The licence guarantees your right to fork. It does not oblige anybody here to help you maintain one.

Nothing here is unusual. It is written down so that the absence of a reply is understood as a volunteer being busy rather than a snub.

## Decisions worth arguing about in public

Open a [discussion](https://github.com/orgs/scalar-app/discussions) rather than an issue when the question is:

- Should Scalar do this at all
- Which repository does this belong in
- A change to the data model, the API contract or the AI safety rules

Those are the decisions that are expensive to reverse. Everything else is fine as an issue or a pull request.

## Changes to this page

Same as any other change: a pull request, reviewed by the maintainer. If governance ever needs to be more than this page, that is a sign the project grew, which would be good news.
